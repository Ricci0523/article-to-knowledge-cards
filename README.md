# make-knowledge-cards

> 把一篇文章变成一小组真正值得复习的知识卡片：常规 5–8 张，撑不起时更少。

`make-knowledge-cards` 是一个 **Skill**（智能体技能包），用于把一个支持 Agent Skills 的智能体从"总结"切换到"决定什么值得留下"。

## 项目解决什么问题

读懂一篇文章之后，真正需要的不是一份内容齐全的摘要，而是一小组过几天还愿意回头看、并且每一条都值得信任的卡片。这两件事方向相反：**摘要保留一切、只是降低分辨率；复习材料必须丢掉绝大部分内容，只留下会改变理解或行动的那几点。**

通用摘要在做复习材料时有四个具体毛病：

| 毛病 | 后果 |
|---|---|
| 重要与不重要混在一起 | 读者无法判断哪一条值得花时间，于是整体都不被信任 |
| 凑数 | 为凑够张数而拆点、填充边角信息，看起来完整，实际什么都没留下 |
| 补写原文没有的内容 | 读者无法拿卡片对照原文验证，卡片失去可信度 |
| 换个说法重复同一件事 | 同一个知识点出现两三次，浪费读者的注意力 |

这个项目把"什么值得留下"从一次性的临场判断，固化成一套可复用的筛选标准、写作规则和自检清单，写进 `SKILL.md`，让任何加载它的智能体都按同一套标准产出卡片。

## 主要功能

**输入**

- 对话里粘贴的文章、笔记、讲稿、文档正文
- 本地 `.md` / `.txt` 文件；TXT 若 UTF-8 解码失败，会依次尝试 GB18030/GBK 与 Latin-1

**输出：每张卡片四个部分**

| 部分 | 内容 |
|---|---|
| 标题 | 知识点本身，写成一个主张或一个问题，而不是一个话题标签 |
| 核心知识 | 一到两句，脱离原文也能独立成立 |
| 简明解释 | 二到四句，讲清为什么成立或怎么起作用 |
| 例子或自测 | 原文已有的例子，或一个问题加参考答案 |

**提取规则**

- **按五条测试筛选**：是否改变行为 / 是否承载机制 / 是否承重（别的结论依赖它）/ 是否是一条区分或边界 / 是否是论证所依赖的具体事实。作者简介、排版说明、修辞性提问、纯叙事铺垫、口号、changelog 条目一律丢弃。
- **一张卡片只讲一个知识点**：出现"而且／另外"连接两个独立主张时，就是该拆开的信号。
- **一个东西一张卡片，不是一个属性一张**：同一个功能的大小上限、支持格式、权限、套餐分层属于"一个东西"，写进同一张卡片。
- **跨段落去重**：以"是否在说同一个主张"为标准合并，不看措辞，也不看它在原文中的位置。
- **不编造**：不补原文之外的背景；原文没给"为什么"时不替它编一个；沿用原文词汇，不改用原文没有的术语；原文没有例子时写自测题，而不是自己造一个例子。
- **信息不足不凑数**：短公告、发布说明通常只支撑 1～3 张，会写明原因而不是硬凑到 5 张。
- **超过 8 条时取舍**：取最重要的 8 条，并用一行说明留下了什么。

**行为**

- **语言**：默认跟随原文（中文原文出中文卡片，英文原文出英文卡片）；用户明确指定语言时按指定输出。
- **输出位置**：粘贴文本 → 直接在对话里给出卡片；指定文件 → 在源文件旁写出 `<源文件名>-knowledge-cards.md`，对话里只给一行摘要和文件位置。**已存在的文件不会被覆盖。**
- **没有知识可提取时**：直接说明并**不产出卡片**，同时给出可行的替代方向，而不是硬造原文没有讲授的道理。

## 安装方法

技能就是一个目录，**没有依赖、没有脚本、没有构建步骤**。把 `skills/make-knowledge-cards` 整个目录放进智能体的技能扫描目录即可：

| 智能体 | 放置位置 |
|---|---|
| DeepSeek Harness | `<项目>/.dsh/skills/`、`<项目>/.agents/skills/`、`~/.dsh/skills/` 或 `~/.agents/skills/` |
| Claude Code / Claude | `~/.claude/skills/` |
| Codex | `~/.codex/skills/` |

```bash
# 例：装到 DeepSeek Harness 的用户级技能目录
mkdir -p ~/.dsh/skills
cp -r skills/make-knowledge-cards ~/.dsh/skills/
```

技能靠 `SKILL.md` 里的 frontmatter 被发现，不需要注册，也不需要改配置。

### 目录结构

```
skills/make-knowledge-cards/
├── SKILL.md          # 技能本体：筛选标准、写作规则、输出格式与边界
└── agents/
    └── openai.yaml   # 面向界面的元数据（展示名、简介、默认提示词）
```

`agents/openai.yaml` 是给产品界面读的（技能在列表里的名称、一句话简介、默认提示词），不参与推理。技能刻意不带 `scripts/`——产出完全由判断决定，加脚本只会扩大维护面。

## 使用方法

### 触发

用日常说法提出需求就会触发，不需要记命令：

- `把 /path/to/article.md 转成知识卡片`
- `这篇文章帮我做成学习卡片`
- `读一下 notes.txt，提炼成复习卡片`
- `Turn this article into knowledge cards`

也可以直接点名：`用 make-knowledge-cards 处理这个文件`。

### 输入范围

| 支持 | 暂不支持 |
|---|---|
| 对话里粘贴的文章、笔记、讲稿、文档正文 | 网页链接（不做抓取） |
| 本地 `.md` / `.txt` 文件 | PDF、Word 等二进制文档 |
| 中文、英文等任意语言的原文 | Anki / 间隔重复软件的牌组文件 |
| | 图形界面 |

### 可以指定的东西

- **语言**：默认跟随原文；说"给我中文知识卡片"，英文原文也会产出中文卡片。

## 输入输出示例

### 示例一：中文短文 → 2 张卡片

**输入**（`pomodoro.md` 节选）

> 番茄工作法把工作切成 25 分钟一段，每段之间休息 5 分钟，每四段之后休息更久。固定的时长本身没有"一定会停"这个承诺重要：因为终点始终很近，开始的心理成本就降低了；而穿插的休息，挡住的是长时间不间断工作必然出现的质量下降。有人把时长改成 50 分钟，只要保留每段之后的休息和停止，效果并没有变差；真正出问题的是那些为了赶进度把休息取消掉的人。

**输出**（`pomodoro-knowledge-cards.md`）

```markdown
# 番茄工作法 知识卡片

## 1. 番茄工作法用固定的短时段与休息交替，而不是连续工作

**核心知识**：工作被切成 25 分钟一段，每段之间休息 5 分钟，每四段后休息更久。

**简明解释**：这套结构的重点不是数字，而是"一定会停"这个承诺：终点始终很近，开始的心理成本就降下来了；穿插的休息则挡住了长时间不间断工作带来的质量下降。

**自测**：在番茄工作法里，25 分钟这个数字本身承担了关键作用吗？

**参考答案**：没有。原文说固定时长不如"一定会停"这个承诺重要，起作用的是结构，不是那个具体数字。

## 2. 短时段的收益来自降低开始成本，而不是时长本身

**核心知识**：番茄工作法真正的机制是让每次开始都变得便宜。

**简明解释**：原文明确说固定时长没那么重要，起作用的是终点可见。因此把 25 分钟改成别的长度，只要保留"一定会停"，机制仍然成立；反过来，取消休息和停止，这个机制就不复存在。

**例子**：有人把时长改成 50 分钟，只要保留每段之后的休息和停止，效果并没有变差；出问题的是那些为了赶进度取消休息的人。
```

这组卡片没有第 3 张"休息能防止质量下降"——那句话是第 1 张解释的后半段，不构成独立主张，在去重环节被合并掉了。

### 示例二：信息稀薄 → 2 张 + 原因说明

一则只讲得清一两个知识点的产品更新公告，会给出 2 张卡片并注明原因，而不是把「5 GB 上限」「CSV/JSON 格式」「管理员权限」「付费套餐」拆成 4 张来凑数——这些是同一个功能的属性，属于同一张卡片。

```markdown
# 产品更新：批量导出功能上线 知识卡片

## 1. 批量导出把「逐个项目导出」换成了一次导出整个工作区

**核心知识**：工作区管理员可以在「设置 - 数据」页面一次性导出工作区内的所有项目，导出格式为 CSV 和 JSON 两种。

**简明解释**：在此之前，导出只能逐个项目手动进行，一个项目一次操作，对拥有几十个项目的团队来说非常耗时；批量导出把这个过程压成一次操作。单次导出的数据量上限为 5 GB，超过上限时系统会自动把任务拆分成多个文件，并发送邮件通知下载链接，链接的有效期是 7 天。

**自测**：一次要导出的数据超过 5 GB 时，用户需要自己把任务拆开吗？

**参考答案**：不需要。系统会自动把任务拆分成多个文件，并发送邮件通知下载链接，链接 7 天内有效。

## 2. 批量导出只对工作区管理员和付费套餐开放

**核心知识**：批量导出的操作者是工作区管理员，且对所有付费套餐开放；免费套餐的用户仍然只能逐个项目导出。

**自测**：一个免费套餐的工作区成员，能用批量导出一次拿到全部项目吗？

**参考答案**：不能。批量导出对所有付费套餐开放，并且要由工作区管理员操作。

本文是一次单一功能的产品更新，可提取的知识点不足 5 个，因此只做 2 张卡片；文中提到的两条问题修复未单独成卡。
```

### 示例三：没有知识可提取 → 不产出卡片

面对一首诗、一张收据或纯叙事文本，它会直接说明"这里没有可提取的知识点"并**不产出卡片**，同时给出可行的替代方向（例如改成赏析或写作技巧分析），而不是硬造出原文并未讲授的道理。

### 示例四：英文原文 → 英文卡片

**输入**（一则英文写作指南的片段）

> Badges are worth having but they have a budget. Five is usually the point where the top of the file stops being a description and starts being decoration.

**输出**（英文原文用英文标签）

```markdown
## 3. Badges have a budget, and five is usually the limit

**Core knowledge**: Badges are worth having, but five is usually the point where the top of the file stops being a description and starts being decoration.

**Explanation**: The badge row sits on the first screen, so badges past the budget compete with the one sentence the reader is looking for. The text keeps the build status, the version, and the license as the ones that are useful to a first-time visitor, and calls anything beyond them mostly noise — to be moved into a section further down or dropped.

**Self-check**: Which three badges does the text treat as useful for a first-time visitor, and what should happen to the rest?

**Answer**: The build status, the version, and the license; anything beyond them is mostly noise and can move into a section further down or be dropped.
```

## 已知限制

- **不做网页抓取。** 给链接无法读取，请粘贴正文或先把页面存成 `.txt` / `.md`。
- **不读 PDF / Word 等二进制文档。** 请先转成纯文本。
- **不导出 Anki 牌组。** 只产出 Markdown 卡片；需要牌组文件是另一件事。
- **没有图形界面。** 只在对话和 Markdown 文件层面工作。

## 验证与测试

技能结构通过官方 `quick_validate.py` 校验（该脚本来自 skill-creator，Anthropic 与 OpenAI 两个版本均通过）：

```bash
# 需要 skill-creator 里的 quick_validate.py，它依赖 PyYAML
python quick_validate.py skills/make-knowledge-cards
# 输出：Skill is valid!
```

开发过程中用 6 类文章做了端到端测试，覆盖这个技能主要的判断难点：

| 文章类型 | 语言 | 预期 | 实际 |
|---|---|---|---|
| 科普说明文（机制、因果） | 中文 | 提取机制类知识点，并保住实用结论 | 5 张，机制与"睡前复习窗口"等结论均保留 |
| 操作指南（方法、阈值） | 英文 | 跟随原文语言，保留判据与阈值 | 7 张，英文标签 |
| 观点评论（主张、反驳、反例） | 中文 | 只留主张与论证，剔除修辞 | 7 张，修辞未混入 |
| 短文 / 产品公告（信息稀薄） | 中文 | 不凑数 | 2 张 + 原因说明 |
| 密集技术笔记（知识点 > 8） | 英文 | 取最重要的 8 条并说明取舍 | 8 张 + 取舍说明 |
| 诗歌（无知识可提取） | 中文 | 不产出卡片 | 不产出 + 替代方向 |

测试暴露并修掉了四类问题，都已写进 `SKILL.md`：

1. **把同一个功能的各个属性拆成多张卡片凑够 5 张**（5 GB 上限、CSV/JSON、管理员权限、付费分层被拆成 4 张）。→ 增加"一个东西一张卡片，不是一个属性一张"，并明确短公告通常只支撑 1～3 张。
2. **原文没给"为什么"时自行编造理由**（薄源公告里每张卡片都补了一段原文没有的动机）。→ 明确"不要替原文补上缺失的原因"，并说明一句话的解释是诚实的答案。
3. **把原文没有的术语写进卡片**（原文只说"海马体把记忆搬给新皮层"，卡片写成了"陈述性记忆"）。→ 明确要求沿用原文词汇，原文没有的术语就是原文没有的信息。
4. **把发布说明里的 bug 修复条目做成卡片**。→ 明确把 changelog / 修复清单归入"不构成知识"的一类，因为读者不会把它带到别的情境里。
